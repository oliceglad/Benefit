# Переписка работодателя и кандидата

## Объём

`/messages` доступен обеим ролям. Диалог открывается по
`/messages/{conversationId}`. Реализованы список, поиск и фильтр непрочитанных,
история с загрузкой предыдущих 50 сообщений, отправка текста и вложений,
отметки прочтения и просмотр завершённого диалога. Новые задания и прохождение
тестов эта итерация не меняет; существующие события показываются в истории.

Формы сообщений повторяют две округлые части знака Benefit: исходящие имеют
прямую левую сторону и округлую правую, входящие зеркальны. Следующие друг за
другом сообщения сближены. Используются текущий синий цвет продукта, светлые
поверхности и системный гротеск. Градиенты и новые зависимости не добавлены.

## Существующие контракты

Публичные операции чата сохранены в `openapi/chat.openapi.json`, клиент
воспроизводится командой `pnpm api:generate`. Внутренние операции и операции
заданий не включены в выбранные paths. Схемы исходного сервиса сохранены.

| Сценарий | Операция |
|---|---|
| Диалоги | `GET /api/v1/chat/conversations` |
| Один диалог | `GET /api/v1/chat/conversations/{id}` |
| История и курсор `before` | `GET /api/v1/chat/conversations/{id}/messages` |
| Сообщение | `POST /api/v1/chat/conversations/{id}/messages` |
| Прочтение до видимого сообщения | `POST /api/v1/chat/conversations/{id}/read` |
| Файл | `POST /api/v1/chat/conversations/{id}/attachments` |
| Скачать файл | `GET /api/v1/chat/attachments/{id}` |
| События | `WS /api/v1/chat/ws` |

HTTP использует общий cookie/CSRF/refresh-транспорт с таймаутами. Для скачивания
добавлен явный режим Blob независимо от MIME-типа; ошибки по-прежнему читаются
как ошибки API. Максимум 10 файлов по 20 МиБ, список расширений соответствует
текущему сервису. Сервер остаётся источником окончательной проверки файла.

WebSocket авторизуется существующей HttpOnly cookie; токены не читаются и не
передаются в URL. Прокси Vite поддерживает upgrade. События обновляют запросы
TanStack Query, после восстановления соединения данные перечитываются.
При разрыве используются REST-обновления и переподключение с увеличением
интервала до 30 секунд. Для отказа авторизации предусмотрено ручное
переподключение после восстановления HTTP-сессии. Статус соединения не
обозначает присутствие собеседника онлайн.

Повтор неизменённого сообщения использует прежний `client_id`, даже после
перехода между диалогами. Автоматического повтора мутаций нет. Пузырь появляется
после ответа сервера; при ошибке текст и файлы остаются в черновике.
Черновики живут только в памяти страницы, сохраняются при выборе другого
диалога; выход из раздела и перезагрузка предупреждают об их потере.
При уходе из диалога незавершённая загрузка файла прерывается. Уже загруженные,
но не отправленные файлы удаляются существующей серверной очисткой orphan-файлов.

Прочтение отправляется только для открытого диалога, когда страница видима,
в фокусе и история прокручена к последнему сообщению. Чтение старой истории
не прокручивает её автоматически при новых сообщениях. Завершённый диалог
оставляет историю доступной и скрывает поле отправки.

## Ограничения API для backend-команды

- Диалоги создаются сервером после отклика или приглашения. Отдельного
  клиентского создания произвольного диалога нет.
- В ConversationResponse нет имени/фотографии кандидата или имени рекрутера.
  Работодатель видит «Кандидат · короткий ID», соискатель — название компании.
  Для персонализации нужен согласованный серверный контракт.
- ID вакансии в ConversationResponse отсутствует; название и источник
  отображаются без выдуманной ссылки на вакансию.
- Нет контракта присутствия онлайн; статус соединения относится к клиенту.

Backend, gateway и инфраструктура не изменены. Бейджи английских имён веток
`main`, `people`, `technical` удалены из общего графа пайплайна; русская легенда,
линии и узлы сохранены.

## Проверка

Проверки этой итерации: TypeScript, lint, production-сборка и короткий проход
локальных диалогов обеих ролей. Подробные автотесты отложены по просьбе
пользователя. Мобильный проход не выполнялся. Загрузка новых файлов через
браузер в этом проходе не выполнялась.

В живом локальном окружении обе синтетические роли отправили сообщения;
кандидат увидел сообщения работодателя, счётчик непрочитанных обновился.
Проверены отправка по Enter, сохранение черновика при смене диалога,
предупреждение при выходе, скачивание существующего `portfolio.md` и сохранение
переписки после перезагрузки. Большая история с несколькими страницами,
ошибки загрузки файлов и имитация сетевых сбоев оставлены на поздний проход.
