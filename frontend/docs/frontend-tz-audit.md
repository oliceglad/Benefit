## Обязательный сценарий ТЗ

| Требование | Реализация и проверка |
|---|---|
| Работодатель описывает потребность команды | Создание и редактирование в `/talent`, существующий API needs |
| Основой служат тесты и подтверждённая категория | Банк и новые потребности по умолчанию требуют подтверждённый грейд; ранее сохранённые настройки не меняются молча |
| Фильтры специализации, категории, стека и подтверждённых достижений ФСП | Банк, категории из ответа API, стек all/any, ФСП есть/нет/любой |
| Подбор с объяснениями | Серверные категории, оценка, причины, недостающие навыки, вклад ФСП и подсказки расширения; фронтенд не вычисляет собственный скоринг |
| Уточнение требований с сохранением контекста | URL, чипы условий, предыдущая выдача во время запроса; черновик фильтров сохраняется при смене сортировки и раскрытии карточки |
| Работодатель первым приглашает кандидата | В существующей карточке банка/подборки; необязательная связь с вакансией, компания, описание, обязательная вилка от–до RUB |
| Решение кандидата и доступ к контактам | Входящие/отправленные, принятие/отказ/отзыв; контакты и чат по серверным правилам |
| Компания с описанием, отраслью и контактами | Рабочий `/company`; первичная настройка перед потребностью/вакансией сохранена |
| Пользователь без истории ФСП | Допускается; отсутствие данных не выдаётся за плохую квалификацию |

## Что доработано в этой итерации

- Режимы «Весь банк» и «По потребности команды», сохранённые потребности
  и действия в одном разделе. Работодатель после входа попадает в `/talent`.
- Добавлены поддерживаемые сервером отрасль, максимальный опыт и бюджет
  кандидата; проверяется диапазон опыта. Главные условия видны сразу,
  дополнительные собраны в раскрываемой группе.
- Активные условия можно убрать по одному. Банковые фильтры сохраняются при
  переходе к потребности и обратно. При обновлении прежняя выдача видна, но
  недоступна для действий до получения ответа. Данные не переносятся между
  аккаунтами; подборки также разделены по потребностям.
- `verified_skills` из main отображаются отдельно от заявленных навыков.
  Снимок talent OpenAPI дополнен полем, клиенты пересозданы Orval.
  Старый ответ без поля поддерживается; некорректные проценты не отображаются.
- Приглашения адаптированы к перенесённому клиенту вакансий. Архивные/закрытые
  вакансии не предлагаются; ошибочный ответ не принимается за список.
- По п. 2.2 ТЗ описание предложения стало обязательным. Подставляются задачи
  потребности или описание вакансии; пользовательский текст не перезаписывается.
  Обеим сторонам явно указан способ связи: чат Benefit после принятия.
- Логотип компании доступен только при объявленном сервером `has_logo`.
  В main без этой возможности используются инициалы, запросов к
  неподдерживаемому endpoint нет.

## Границы и ограничения

`needs/{id}/matches` принимает пагинацию и `hide_contacted`, но не ручные
фильтры банка. Поэтому ФСП как строгий фильтр применяется к банку; в подборке
его вклад приходит от серверного скоринга. Фильтры конкретного мероприятия,
дисциплины и места этим API не предусмотрены. Серверные правила не вводились.

Сортировка ФСП использует число доступных достижений, затем активность.
Она не означает ранжирование по ценности каждого места. Скрытые достижения
не раскрываются. ТЗ разрешает синтетический набор ФСП и не требует реального API.

Вакансии/самостоятельные отклики, задания и мобильное приложение необязательны
для MVP. Существующие вакансии и конструктор сохранены; интеграция конструктора
с `/api/v1/hiring` и серверное сохранение шаблонов остаются отдельной задачей.
PUT компании не имеет ETag/версии: конкурентную перезапись фронтенд предотвратить
не может. Это ограничение контракта, а не повод изменять backend в этом проходе.

## Проверки перед main

Пройдены 145 тестов в 41 файле, TypeScript, ESLint и production-сборка после
объединения. Добавлены проверки диапазонов/URL, сохранения черновика при смене
сортировки, предыдущих результатов при уточнении, изоляции аккаунтов, повтора
ошибочного запроса, подтверждённых навыков и старого контракта без них.

Через живой локальный gateway проверены банк, отрасль/опыт/бюджет, пустая выдача
ФСП и удаление одного условия, восстановление URL, выбор сохранённой потребности,
объяснения и недостающий Kafka, новая потребность с подтверждением по умолчанию,
форма приглашения с зарплатой/компанией/вакансиями и рабочая компания.
Приглашения при этой проверке не отправлялись, тестовые данные не изменялись.

В живой базе три синтетических кандидата, один с подтверждённым грейдом;
нет видимых достижений ФСП и отдельных результатов навыков. Заполненные
verified_skills проверены тестами. Пагинация большого каталога и полный цикл
нового приглашения не заявляются как пройденные в браузере в этой итерации.

Дополнительно проверены список вакансий, отправленные приглашения и адаптивная
компоновка на 390 и 1440 px: горизонтального переполнения не обнаружено.
Сборка сообщает о существующем общем чанке 567 kB; ошибок сборки нет.
