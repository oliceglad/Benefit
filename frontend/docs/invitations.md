# Приглашения и обязательные дополнения

Реализовано 11.10.2026 только во frontend. Новых маршрутов нет.

## Основной сценарий P0

- В раскрытой карточке `/talent`, включая подборку потребности, доступна отправка
  персонального предложения. Из потребности подставляются название, формат,
  город и рублёвый бюджет. Можно выбрать собственную незакрытую вакансию.
- Название компании, должность и обе границы зарплаты обязательны. Вилка в RUB;
  суммы целые, от 0 до 100 000 000, нижняя граница не выше верхней.
- В существующих `/messages` добавлена вкладка приглашений обеих ролей:
  входящие/отправленные, фильтр статуса, условия, срок, решение и отзыв.
  Выбранное приглашение сохраняется в URL.
- Принятие/отказ/отзыв подтверждаются диалогом. Статус меняется только по ответу
  сервера. Контакты показываются только работодателю для принятого приглашения
  и только при `contact_access=granted` публичного профиля.
- Диалог определяется серверным `source=invitation` и `invitation_id`.
  При задержке обработки отображается ожидание и доступна повторная проверка.
- Запросы и кеш разделены по аккаунту; используется общий cookie/CSRF-транспорт
  с таймаутом и AbortSignal. Несохранённая форма защищена от случайного выхода.

Композиция функций расположена в `app/pages/talent-page` и
`app/pages/messages-page`; features не импортируют приватные файлы друг друга.
Черновики чата сохраняются в родительском workspace при смене вкладки.

## Дополнения P1

- Профиль компании раскрывается в `/vacancies`: просмотр и сохранение описания,
  отрасли, города, сайта, реквизитов, размера команды, стека и контактов.
- Перед публикацией вакансии проверяются обе границы в RUB. Та же проверка
  применяется при сохранении уже опубликованной вакансии. Черновики допускают
  незаполненную вилку; ранее опубликованные данные автоматически не меняются.
- В предпочтениях кандидата добавлены ФСП ID, проверка связи, синхронизация,
  список достижений и состояния отсутствия истории/ошибки. Подтверждённые
  результаты не редактируются вручную. Перед привязкой/синхронизацией нужно
  сохранить текущий шаг.
- Вход ФСП доступен, если `/auth/providers` объявляет `fsp_id`. Для возврата после
  привязки backend должен настроить `OAUTH_FRONTEND_CALLBACK_URL` на адрес
  существующего frontend `/profile?section=preferences` или `/`. Параметр
  `linked=fsp_id` сам по себе не считается подтверждением связи: нужна синхронизация.

## Проверка и ограничения

Пройдены build/TypeScript, lint и три целевых теста зарплатных условий.
В браузере через живой gateway отправлены два синтетических приглашения:
одно принято, второе отклонено. Проверены входящие, отправленные, переход
в соответствующий чат и показ разрешённых сервером контактов работодателю.
Сохранено синтетическое контактное лицо компании с сохранением остальных полей.
Проверено состояние несвязанного ФСП ID. Отзыв реализован, отдельно живой
отправкой не проверялся. Полная внешняя привязка ФСП и получение реальной истории
не проверялись; зависят от провайдера и серверных настроек. Мобильный вид и полный
регресс по просьбе пользователя пропущены. Дальнейшие проверки остановлены
по запросу пользователя перед пушем.

Backend и инфраструктура не изменялись. Реальные процессы `/api/v1/hiring`
и серверное хранение шаблонов конструктора пайплайнов остаются отдельной работой.
