# Подбор кандидатов

Актуально на 11.10.2026. Сверка ТЗ, веток и ограничений — в
[frontend-tz-audit.md](frontend-tz-audit.md). Новые изменения относятся только
к frontend. Работодатель открывает `/talent`; кандидат к экрану не допускается.

## Банк и условия поиска

«Весь банк» использует `GET /api/v1/talent/candidates` из matching-service.
По умолчанию показываются профили с подтверждённым тестом грейдом. Статус
можно изменить явно. Основные поля: поиск, специализация, несколько грейдов,
подтверждение, стек all/any и наличие доступных подтверждённых достижений ФСП.
В «Условия, опыт и активность» находятся отрасль, город, формат работы, опыт
от–до, максимальные ожидания зарплаты, актуальность и включение не ищущих работу.
Диапазон опыта валидируется до отправки; условия применяются целиком кнопкой.

Активные фильтры показаны чипами и удаляются по одному. Категории из ответа API
позволяют сузить специализацию/грейд/подтверждение. Сортировки соответствуют API,
размер страницы — 12. Условия, сортировка, страница и раскрытая карточка хранятся
в URL. Смена сортировки и раскрытие не теряют введённый черновик фильтров.
Применение сохраняет текущую сортировку; изменение условий сбрасывает страницу.

При новом запросе прежняя выдача остаётся на экране с индикатором обновления;
действия с ней блокируются до ответа. Ошибка отображается с повтором запроса.
Кэш и промежуточные данные изолированы по аккаунтам; профили в localStorage
не сохраняются.

## Потребности и объяснения

«По потребности команды» выбирает сохранённые требования; «Новая потребность»
открывает редактор в том же разделе. Если компания не создана, сначала
открывается первичная настройка с возможностью вернуться в банк.
Потребность сохраняется через API и не публикуется как вакансия.

Название, задачи команды, роль, грейд, обязательные/желательные навыки, бюджет,
город, форматы и число сотрудников сохраняются. Новые потребности по умолчанию
требуют подтверждённый грейд; ранее сохранённые false сохраняются с пояснением.
В «Точности подбора» доступны допустимое отклонение грейда, минимальный опыт и
строгие условия стека, бюджета и формата. Необязательные поля можно очищать;
ранее сохранённая валюта не заменяется молча. Есть валидация строгих условий,
защита несохранённой формы, блокировка дубля отправки, закрытие и возобновление.

Результаты показывают серверные категории, оценку из 100, причины, предупреждения,
совпавшие/близкие/недостающие навыки и вклад компонентов оценки. Оценка не является
вероятностью найма. Подсказки расширения ведут в редактор, без автоматического
изменения требований. Потребность, страницы, скрытие уже контактированных и
карточка сохраняются в URL. Кэш разделён по аккаунту и потребности.

API matches не принимает банковые фильтры. Они остаются в URL для возвращения
к банку; не отправляются в неподдерживаемый endpoint. Строгий фильтр ФСП есть
в банке, а вклад ФСП в оценку потребности возвращается сервером.

## Карточка и приглашения

Карточка показывает подтверждение категории, тест/результат, условия и активность.
`verified_skills` из main отображаются отдельно от заявленных навыков; старый API
без них поддерживается. ФСП раскрывает мероприятие, дисциплину, уровень, место,
результат, команду, дату и безопасную HTTP(S)-ссылку, если сервер их предоставил.
Отсутствие доступных достижений не доказывает отсутствие истории участия.

Приглашение открывается прямо в карточке. Зарплата/роль/формат берутся из
потребности, компания — из общего профиля. Обязательны корректная вилка от–до
в RUB и предложение; связь с вакансией необязательна. Закрытые/архивные вакансии
не предлагаются. Статусы, повторное приглашение, входящие/отправленные, решения
и чат используют существующий модуль; подробнее [invitations.md](invitations.md).
Контакты открываются по серверным правилам после принятия приглашения или отклика.

## Ограничения проверки

Проверки и результаты записаны в актуальном аудите. На живых данных доступны
три синтетических профиля и один подтверждённый Senior с результатом 94,1%.
Фильтры, восстановление URL, объяснение оценки 68/100 и недостающий Kafka,
пустое состояние ФСП, редактор и заполнение приглашения проверены на gateway.
Новых приглашений в этой итерации не отправляли. Заполненные verified_skills
проверяются компонентными тестами; в локальном API их пока нет.
